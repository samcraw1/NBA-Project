NBA Project — Architecture

Two independent paths today: a live path serving the frontend directly from NBA.com, and a historical pipeline that extracts and transforms season data to local CSV. They are not yet wired together — the pipeline's output isn't loaded into a database or served by the API. Dashed boxes below are planned, not built.

Where the project stands (roadmap)

  • 1. Data extraction — done. Game logs, teams, and players all extract via extract.py, with bounded retries on the live call.
  • 2. Data transformation — in progress. Schema checks, safe shooting %, and the merge across games/teams/players are done in transform.py; join cleanup (duplicate id columns) is the remaining loose end.
  • 3. SQL and data modeling — not started. No local Postgres, no migrations yet.
  • 4–5. ETL pipeline / analytics — not started.
  • 6. AWS and Terraform — not started. Terraform and AWS CLI are installed locally; current AWS credentials are root-account keys, which should be replaced with a least-privilege IAM user before any provisioning.
  • 7–8. Orchestration / ML — not started.
